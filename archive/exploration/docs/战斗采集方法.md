## 一、机动：**三步**协议（★ 位置 bug 的根因）

```
① com/ComPost.asp?ObjID=<单位>&Command={"<单位>":{"move":"<mapid1>,<mapid2>","speed":0}}
     &ObjColor=<阵营>&TaskName=机动&ObjPos=<格号>&MapID=<格号>      → 返回空串（受理）
② com/updatePos.asp?ObjID&MapID=<目标格 mapid>&ObjRot=180
     &GridType=<目标格 hextype>&MapStep=<目标格 step>
     &preIDhex=<起格 hex 属性>&posIDhex=<目标格 hex 属性>&posIDcond=<目标格 cond>
     &HuiHe&steep&ComID&Index&Speed&RoomDay&RoomWeather&MineArea&GasArea&Bridge
     &EleLow=145&EleDiv=5                                          → 返回**本格机动耗时 ms**
③ com/MoveEnd.asp?ComID=<①的ComID>&ObjID=<单位>&StageID=0&RoomSecond=0
     &ObjPos=<起格 mapid>&ObjNewPos=<目标格 mapid>&MoveFlag=0
```

**★ 关键：新位置的唯一来源是 ③ 的 `ObjNewPos`，且必须是 mapid（不是格号）。**
受控实验 `tools/hex_move_probe.py`（5 组参数）：

| 变体 | `ComPost.ObjPos/MapID` | `updatePos` | `MoveEnd.ObjNewPos` | 服务端 pos |
|---|---|---|---|---|
| 传格号 | 格号 | 调 | 格号 | ✘ 变成格号（如 3435） |
| 传 mapid | 格号/mapid 都行 | 调或不调 | **mapid** | ✔ 正确（如 170035） |

- 只调 `updatePos` **不改位置**（只返回耗时 ms）。
- 只调 `ComPost` **也不动**。必须三步齐全。

## 二、开火：**直调 `com/Attack.asp`**（★ 不是 ComPost）

客户端 `CommandAttack` 的真实请求：

```
GET com/Attack.asp
  ?ObjID=<射击方>&TarID=<目标>
  &ObjPos=<射击方 mapid>&TarPos=<目标 mapid>
  &ObjType=<射击方 typeid>&TarType=<目标 typeid>
  &Dist=<六角格距离>&ObjEle=<射击方高程>&TarEle=<目标高程>
  &TarHex=<目标格 hex 属性>&TarHexType=<目标格 hextype>
  &WeaponID=<武器 data ID，不是索引！>&TarStack=<目标格是否堆叠 0/1>
  &StageID=<RoomRound>&GuideID=&ComID=&RoomSecond=
  &ObjA0=<射击方 a0>&ObjF3=<射击方 fort>&AttackRot=<射击方向>
  &RoomDay=0&RoomWeather=0&Time1=
```

- **返回非空 = 成功**；空 = 射击失败。
- **战果不在返回值里**，靠**下一帧 `ObjAjax.asp`** 下发（`blood`/`keep` 变化）。
- `WeaponID` 取该单位 `wz` 列表里的 **data ID**（`engine/equip.py`：如 69=车载导弹、71=便携导弹）。

## 三、读结果：`Report_Attack.asp` → **`Caijue.asp?ID=`**（★ 金矿）

`com/Report_Attack.asp` 返回**最近一条战报**（HTML），形如：

```html
<em>第1分钟战报</em>
<p><a class="text-BLUE" href="javascript:Caijue(128241)">蓝方反坦克排B班射击红方坦克1排(无效)</a></p>
```

其中 `Caijue(<数字>)` 的**数字就是裁决 ID**。`Caijue.asp?ID=<id>` 返回**该次战斗的完整裁决明细**，
结构固定为两张表（**GBK 标签 + UTF-8 值的混编页**，读取时两种编码都要试）：

```
【行进间射击裁决】  射击单位 | 蓝方反坦克排B班 | 目标单位 | 红方坦克1排
                    武器     | 便携导弹        | 距离     | 0格
                    高度差   | 不修正          | 攻击等级 | 7
                    随机数   | 7               | 战斗结果 | 2
【战斗结果修正】    射击单位状态 | 机动中   | 目标状态 | 机动
                    随机数(?)| 5              | 装甲级别 | 复合装甲
                    修正结果 | -2             | 最终战果 | 压制
```

⇒ **攻击等级 / 随机数 / 战斗结果 / 状态 / 装甲级别 / 修正 / 最终战果 全部下发**
——这就是**经验重建裁决表的直接证据源**，不必再靠手册列对齐去猜。

抓取工具：`tools/hex_fetch_caijue.py <ID> [ID...]`（结果存 `7527_transport_capture/caijue/`）。

## 七、连续开火：必须"武器就绪"（★ 曾经的关键阻塞）

`com/Attack.asp` **每成功一发后**，该单位 `ObjAjax.att` 变为 `1`（武器未就绪），
此时再开火**返回空串 = 射击失败**。必须调一次：

```
com/ObjWeaponReady.asp?ObjID=<单位>     ← 客户端开火收尾调的就是这个
```

实测节奏（`tools/hex_clock_probe.py`）：

```
第1发 返回='1' ✔  att=0
第2发 返回='' ✘  att=1      ← 未就绪
   ObjWeaponReady.asp → ''
第3发 返回='1' ✔  att=0
第4发 返回='' ✘  att=1
第5发 返回='1' ✔  ...
```

⇒ 批量采样时**每发之后都要调 `ObjWeaponReady`**，否则只有一半命中。

## 八、时钟推进：**靠客户端轮询驱动**

`RoomSecond`（`User_Get[20]`）**只在有请求时才推进**：以 ~1 Hz 调 `ObjAjax`/`User_Get` 时
实测 **+1 秒/秒**；若每 5 秒才轮询一次，时钟约只走 1/5 → 曾误判"压制 362 秒不解除"。

⇒ **只要是在等时长（压制解除、攻击间隔），一律用 1 Hz 轮询**。

## 九、倍速（RoomSpeed）

- `RoomSpeed` 是**房间级服务端配置**（`User_Get[16]`，练习服当前 = **3**），
  客户端**只读**（仅用于 `addClock` 显示与 `FlyTime=1200/RoomSpeed` 动画），无设置入口。
- 台账换算：`KeepSec=50` × `RoomSpeed=3` = **150 秒** = 引擎 `SUPPRESS_SEC`；`TireSec=25`（疲劳）。
- 注：用户提示**练习服可开 10 倍速**（平台侧配置）。脚本侧无法设置；若开启，
  按时长换算，等压制/间隔的实测时间可缩短到约 1/3。
