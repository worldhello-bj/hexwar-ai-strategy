## 二、已验证的关系（17/17 全中）

$$\text{最终战果} = \text{战斗结果} + \text{修正结果}$$

- `> 0` → `n，歼灭`（n = 消灭的班数）
- `= 0` → **压制**（印证手册 4.6.2(5)：战果被修正为 0 仍压制车辆）
- `< 0` → **无效**

已验证样例：`2 + (−1) = 1`、`1 + (−1) = 0 → 压制`、`1 + (−2) = −1 → 无效`、
`3 + 0 = 3 → 3，歼灭`、`3 + (−1) = 2 → 2，歼灭`。

## 三、两个随机数的分工（实测，27 条样本）

| 骰 | 位置 | 作用 | 证据 |
|---|---|---|---|
| **随机数1** | 表1 | 查 **战斗结果**（表4/表6 的列） | 同一 `攻击等级 + 随机数1` → 同一战斗结果（确定性） |
| **随机数2** | 表2 | 查 **修正结果**：`修正结果 = 表5[装甲][随机数2 + 状态修正合计]` | **27/27 命中**（`tools/verify_unfavorable.py`） |

**状态修正合计 = 射击算子状态修正 + 目标状态修正**，数值就是**手册表7 的那三个**：

| 字段 | 取值 | 修正 | 来源 |
|---|---|---|---|
| 射击算子状态 | 机动中 | **−1** | 手册表7 |
| 射击算子状态 | 被压制 | **−1** | 手册表7 |
| 目标状态 | 机动 | **−2** | 手册表7 |
| 目标状态 | 掩蔽 | **−2** | 手册表7 |
| 目标状态 | （空） | **0** | 该次裁决里目标无状态 |

⇒ **官方是两颗骰**：随机数1 定「战斗结果」，随机数2 定「修正结果」，最后
`最终战果 = 战斗结果 + 修正结果`。

### ★ 关键更正（2026-10-15，样本 17 条 → 27 条）

早期（17 条）曾把「目标状态恒为机动、修正却变」推断为 **“手册表7 的状态修正本身带随机数”**
—— **该结论是错的**。补样本后发现：`随机数2 = 8` 时修正取 **−1**（目标状态=机动）
与 **0**（目标状态=空）**两种值** ⇒ 变的是**目标状态**，不是表7。真实机制：

```
修正后随机数 = 随机数2 + 射击算子状态修正 + 目标状态修正
修正结果     = 表5[装甲][修正后随机数]
```

把状态修正加进去后 **27/27 全中**（早期 17 条 = 射手机动中 −1 + 目标机动 −2 = **−3** 也一致）。
⇒ 手册表7 的 **−1 / −2 数值**与**表5 的 band 选择**同时被线上数据确认。

- `随机数2` **不影响** 战斗结果（同一 `随机数2=9` 出现过结果 3 与 1）。
- 反例留档：同一 `随机数2=8` → 修正 `{−1, 0}`，故 `修正结果` **不是** `随机数2` 的单值函数。

## 八、★ 裁决合成方式：两颗骰 + 修正加在战果上（**已修复，2026-10-15**）

线上模型（27/27 实证）：

```
战斗结果 = 表4/表6[攻击等级][随机数1]              ← 不受状态修正
修正结果 = 表5[装甲][随机数2 + 状态修正合计]
最终战果 = 战斗结果 + 修正结果
```

`engine/crt.py:direct_fire` **已按此重写**：

```python
if roll is None:      roll = roll2d6(rng)      # 随机数1 → 表4/表6
if fix_roll is None:  fix_roll = roll2d6(rng)  # 随机数2 → 表5/表7
fixed = fix_roll + situational_mod(...)        # 修正后随机数
base  = 表4[攻级][roll]        # 车辆；人员用 表6[攻级][roll]
fix   = 表5[装甲][fixed]      # 车辆；人员用 表7[fixed]
total = base + fix            # 手册 4.6.2(5)(6)
```

「无效 / 压制 / 消灭 n」统一成一条数轴 `无效 = -1、压制 = 0、消灭 n = n`，
于是 4.6.2(5)(6) 就是一条加法；表4 的空白格与表6 的空串都是"无效"（−1）。

**修复前的偏差（留档）**：引擎只用随机数1，并把状态修正 + 表5 的结果**折进查表索引**；
把 `随机数2` 换成 `随机数1` 后，27 条里只有 **7/27** 能对上修正结果。

**修复效果（`tools/verify_unfavorable.py` C/D/E 段）**：

| 断言 | 结果 |
|---|---|
| `修正结果 == 表5[装甲][随机数2 + 状态修正]` | **27/27** |
| `战斗结果 == 表4[攻级][随机数1]`（units=4） | **27/27** |
| **端到端复算「最终战果」** | **27/27（零残差）** |

顺带修掉两处缺陷：

1. `步兵轻武器` 打**人员**时曾被误路由到表4（表4 是"对车辆单位战斗结果"，人员必须走表6）；
2. 表4 的 `table4["7"][16]` 由 3 条独立样本（128246/128249/128264，攻级10/随机数1=7）
   校正为 **3**（原为 4）。

故 `direct_fire` 暂时仍把状态修正折进表10 的行号，**待实测**。
