## 2. 计分侧的两个实测结论（结论相反，必须分情形）

| 情形 | 动作 | 平台计分页变化 | 含义 |
|---|---|---|---|
| **A. 开局同格**（乘员是独立单位） | 打掉一辆满载的红方 ZBD100 | 红 354 → **314**（只 −40） | 乘员的 38 分**分文未动**——车毁没碰到它们 |
| **B. 真装进车里**（`ObjInto` 后） | 打掉装着 1 个步兵班的 ZBD100 | 红 354 → **298**，蓝歼灭 +**56** | **56 = 车体 40（10×4）+ 乘员 16（score 4 × 编制 4）** ⇒ 乘员随车被歼，其编制分从剩余兵力分扣除**并记给对手** |

情形 B 细节（`loadkill_20261015-223027`）：

```
上车：ComPost {"Obj_104792":{"inside":"Obj_104794"}} + ObjInto.asp → 'True'
      乘员变成 pos=0 / blood=0 / color=''，**计分页不变**（354/234）
打掉车：tick 43 车血 0  →  剩余兵力 红 298/蓝 234，歼灭 红 0/蓝 56
车死后：乘员记录**仍在**（pos=0/blood=0/color=''），但 com/Obj2_Out.asp 返回 **'0'**
        ⇒ 放不出来了 —— “记录还在 ≠ 人还活着”
```

## 3. 引擎侧据此做的对齐（`SCORING_VERSION = 6`）

1. `env/hexwar_env.py::load`：按平台把单位置成 `blood=0 / color=''`，
   编制（`engine/equip.py::CARRIED_ESTABLISHMENT`，**五型均为实测值**）写进 `establishment`；
   带伤上车（`blood != 编制`）时记 `aboard_damage_forgotten` 并进 `unverified`。
2. **随车机动**：原来用 `alive()` 过滤乘员，而车内 `blood=0` ⇒ 乘员不会被带走；
   已改为只看"有没有挂在载具上"（与当年 `unload` 踩的是同一个坑）。
3. `unload`：按**编制**恢复 `blood` 与阵营色（平台下车 = 新建实体、`blood`=编制）。
4. `engine/scoring.py`：`remaining` 只在**载具存活**时把车内载员按编制计入；
   载具被歼时把载员的编制分从 `remaining` 扣除、并一并计入对手的 `killed`（= 情形 B）。

回归：`pytest` 216 passed；`verify_rules` 30/30、`verify_rules_extra` 20/20、
`verify_tables` 30/30、`verify_unfavorable` 36/36；`hex_score_audit` 断言通过（引擎 == 平台 354/234）。
