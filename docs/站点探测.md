## 一、第二台服务器：比赛模式服

官方 `readme.txt` 于 **2026/10/13** 公告了两台服务器：

| 名称 | 地址 | 模式 |
|---|---|---|
| 练习服务器 1 | `http://www.hexwar.cn/WARGAMEAI` | 练习模式 |
| 练习服务器 2 | `http://43.143.209.228/WARGAMEAI` | **比赛模式** |

实测结果：

- 两台均在线，大厅与 `readme.txt` 均返回 200，`readme.txt` 内容**完全一致**（499 字节）。
- 两台客户端主页 `WARGAMEAI7/main.html` **同为 7,759 字节、同为 GBK、标题相同**
  → **客户端是同一份**，本仓库的离线客户端对两台都适用。

**实践意义**：练习模式可以单人控双方（导演），比赛模式不行。
也就是说，在练习服上跑通的战术，**必须**考虑到比赛服的计时与通信限制
（见 `readme` 第 4、5 条：比赛时禁用 Ctrl 批量机动；仅无人装备可用 AI）。

> ⚠️ 比赛服是**真实比赛环境**。本仓库**不**对其做任何写入操作
> （不建房、不下令、不登录），仅确认其公开页面可达。

### 装载的契约细节（已核实）

- 客户端会先校验人与车**同格**，否则报「人和车不同格」。
- 装载还有一个**空中通路**：必须处于「超低空」状态才能执行装载任务。
- 装载成功后，**控制权转移到载具**（客户端把 `MyObjID` 置空并搬运 `s1/s2/s3`）。
- 装载/卸载走的是 `ComPost` 的 `on` / `outside` 键，
  而 `ObjInto.asp` 是另一条即时通路。

### 7.3 两个新发现

**（1）`GamePost.asp` — 官方结果上报**

它返回一个自动提交的表单，目标是 `/api/notify/sync/game/result`：

```json
{"requestTime":0,"gameId":"","roomId":"","gameStartTime":0,"gameEndTime":0,
 "winner":"","redScore":0,"blueScore":0,

```

另带隐藏字段 `sign`（签名字串）与 `appId`。

**含义**：官方上报口径把**夺控点分单独统计**（`redCityScore` / `blueCityScore`），

签名与 appId 是防伪造机制，本项目**不接触**。

**（2）`Caijue.asp` — 官方裁决页模板**

| 区块 | 字段 |
|---|---|
| 主裁决 | 射击单位 / 目标单位 / 武器 / 距离（格）/ 高度差 / **攻击等级** / 随机数 / **战斗结果** |
| 结果修正 | 射击单位状态 / 目标状态 / 随机数 / **装甲级别** / 修正结果 / **最终战果** |

官方软件认得的取值：

- 射击单位状态：**被压制、机动中**
- 目标状态：**掩蔽、卧倒、机动、行军、堆叠、居民地、丛林地、水上、工事、建筑物、车内**

注：练习服与比赛服返回**同一份**（904 字节，GB2312）。
此前记录的“`Caijue.asp` 返回空”**是错的**，已更正。

### 8.3 官方计分口径（**只有分项名已确认，分值/公式未确认**）

`MyScore/?UserID=…`（个人中心）的表头给出了**官方分项名**：

```
夺控分   红方夺控分 / 蓝方夺控分
兵力分   红方兵力分 / 蓝方兵力分
战果分   红方战果分 / 蓝方战果分
总分     红方总分   / 蓝方总分
净胜分   红方净胜分 / 蓝方净胜分
```

⇒ **总分 = 夺控分 + 兵力分 + 战果分；净胜分 = 红方总分 − 蓝方总分**（分项名层面）。

这与本仓库 `env.score()` 的 `captured + remaining + killed`、
`diff = own − enemy` 在**结构上**对应；其中**剩余兵力分已按实测口径改写**：

- 平台 `Report_All.asp` 开局实测：**剩余兵力分 红 354 / 蓝 234**；
  引擎现已给出**同样的 354 / 234**（`engine/scoring.py`：
  `Σ上阵(score×blood) + Σ车内载员(score×编制)`）。
  早期口径 `Σscore` 给 75/60、`Σ(score×blood)` 给 207/240，都对不上。
- **夺控分**在全部 33 个采集文件里**恒为 0** ⇒ 每点分值**无法反推**；
  「每个夺控点 10 分」**没有任何依据**，不得当作规则（代码里是显式占位）。
- **歼灭分**同样**恒为 0** ⇒ 公式**无法反推**（代码里是显式假设，随 `pending_rules` 下发）。

⇒ 完整证据与待确认清单：**`docs/计分规则待确认.md`**（可直接转发给主办方）、
`docs/计分对账.md`（复现：`py -3.13 tools/hex_score_audit.py`）。

（另：比赛结果上报接口 `/api/notify/sync/game/result` 把
`redCityScore`/`blueCityScore` 单列，与"夺控分是独立分项"一致。）
