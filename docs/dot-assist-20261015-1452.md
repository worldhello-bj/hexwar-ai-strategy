## 问题一：MoveEnd 的位置字段用了显示格号

确切位置：

- `tools/hex_combat_round.py:153–155`，具体错误表达式在 **154行**。
- 旧工具 `tools/hex_play_round.py:121–123`，同样表达式在 **122行**。

原表达式：

```python
ObjPos=GEO.hexid(frm), ObjNewPos=GEO.hexid(to)
```

原始客户端证据：`snapshot/raw/war.min.js` 的 `CommandMove` 从单位 `pos` 与路径数组取得 `z,t`，把 `t` 写回单位 `pos`，并调用 `CommandMoveEnd(a,b,z,t,...)`。后者把 `c,d` 原样传给 `ObjPos,ObjNewPos`，还用 `$("#"+d)` 定位地图格。因此这里要求 **mapid**。

本机模拟样例：`frm=170068`、`to=170070`，对应显示格号 `3434`、`3435`。当前工具实际把后两个值传入 `MoveEnd`。这与文档记录的“服务端 pos 变成 3435”数值吻合，但尚未通过本次服务器操作证明因果。

最小建议：

```python
# 只改 MoveEnd 的这两个字段；cmd() 必须已经返回唯一匹配的真实 ComID。
ComID=c["com_id"], ObjPos=frm, ObjNewPos=to
```

旧工具对应 `ComID=step["com_id"]`。不要保留无法匹配时的 `or 1`，否则会继续操作无关指令。

**不要统一替换所有带 MapID/hex 名字的字段。** 原客户端在不同接口使用不同口径：

| 位置 | 正确口径 | 当前 combat 工具 |
|---|---|---|
| `Command[unit]["move"]` 路径 | mapid 序列 | 已正确 |
| `ComPost.ObjPos / ComPost.MapID` | 显示格号（`HexID` / `MapArr[].hexid`） | 已正确，保留 `GEO.hexid()` |
| `updatePos.MapID` | 目标 mapid | 已正确 |
| `updatePos.preIDhex / posIDhex` | 原/目标格的 **hex 地形贴图属性** | 已正确，保留 `cell(...).get("hex",0)` |
| `MoveEnd.ObjPos / ObjNewPos` | 原/目标 mapid | 本次指出的差异 |

旧 `hex_play_round.py:117` 仍把 `GEO.hexid()` 填入地形字段；不要把旧实现当作新版的正确参考。

## 问题二：ComID 从整个队列取第一条

确切位置：

- `tools/hex_combat_round.py:111–113`：111行 `re.search(...)`，113行取 `m.group(1)`。
- `tools/hex_play_round.py:104–105`：同样逻辑。

原表达式：

```python
m = re.search(r"(\d+)\|[^|]*\|", echo)
com_id = m.group(1) if m else ""
```

`ComAjax` 是累积队列，而不是本次请求的单独响应。现有 `7527_transport_capture/load_unload_log.md` 已记录：第二次、第三次操作的回显仍以早先的上车指令开头。非空回显不能证明第一条就是当前操作；简单取最后一条同样可能拿到其他单位/操作手的指令。

最小稳妥建议：

1. **提交前**只读取一次当前队列，保存已有 ComID 集合，限定同一房间/同一轮次。
2. 提交本次命令，解析提交后的完整回显 JSON，不能只在截断的300字符摘要里匹配。
3. 过滤为新增 ComID、当前单位及其精确动作参数（例如相同 `move` 路径与 `speed`）；已知当前操作手ID时再匹配该字段。
4. 必须得到唯一匹配。有多个新匹配、没有匹配、房间已切换或协议不支持时停止后续动作；不要回退 `ComID=1`，也不要盲目重新提交。
5. 指令尚未出现时，可只读有界轮询队列；超时仍不能把旧指令当新指令。此过程的服务器验证由 DS 在其明确隔离的练习环境完成。
