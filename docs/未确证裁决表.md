## 0. 实测总抓手（先读这一节）

客户端 `war.min.js` 里的 `loadReport()` 会请求 **`com/Report_Attack.asp`** 并显示战报。
据 `docs/裁决引擎.md`，该接口返回**最近一条裁决**的明细，含：

```
攻击等级（atk_level） | 随机数（骰值） | 各项修正 | 最终战果
```

⇒ **裁决表可以「射击 → 读战报」直接经验重建**，不需要靠单调性去猜列对齐。

**前置条件**（来自 `docs/战斗链路实测.md`）：
1. 想定 7527 开局**双方 144 对单位通视 = 0** → 必须先机动建立通视；
2. 武器与目标类型必须匹配（防空武器打地面装甲拿不到攻击等级）；
3. 距离贴近到 **3~6 格**，别贴射程上限；
4. ⚠️ 脚本重放机动的**位置存错**（存成显示格号而非 mapid）尚未解决 → 战斗采集需走
   **浏览器实操**（用客户端自身的 `CommandMove` / `CommandAttack`），或先修好该 bug。

## E. 计分规则（★ 缺得最多的一块）

官方计分页 `Report_All.asp` 只给**分项名**：夺控点得分 / 剩余兵力得分 /
歼灭对手兵力得分（+ 一行被 HTML 注释掉的「摧毁重要目标得分」）。
总分 = 三项之和，净胜分 = 红 − 蓝（`MyScore` 表头印证）。

| 编号 | 项 | 现状 | 未知点 | 判据 / 实验 |
|---|---|---|---|---|
| **SCORE-CAP** | 夺控分每点分值 | 占位 `CAPTURE_POINT_SCORE_PLACEHOLDER = 10`，**无依据** | 主要/次要是否同分；占领是一次性还是按时间；失守是否扣分；重复夺回是否重复计分；是否封顶 | 全部采集里夺控分**恒为 0** ⇒ 必须**主动去占一个点**再读计分页 |
| **SCORE-KILL** | 歼灭分公式 | "整单位被歼则计其分值" | 是否按**损失兵力**逐点计；载员被歼是否与载具重复计算；与剩余兵力分是否互补 | 全部采集里歼灭分**恒为 0** ⇒ 需一局**整单位被歼**后的计分页 |
| **SCORE-CARRIED** | 车内载员是否计入剩余兵力分 | 当前 `Σscore`，**完全没算载员** | 载员按`编制兵力`还是当前血量计入 | ★ **已反推**：`Σ上阵(score×blood) + Σ载员(score×编制)` 同时精确命中平台的 红 354 / 蓝 234；但缺官方确认与完整编制表 |
| **SCORE-TOTAL** | 终局总分与结算 | `remaining+captured+killed` | 各项权重/上限；时间奖励、任务完成奖励；**提前结束**（全歼/占满）如何结算；**时间耗尽**如何判胜负；平局判定 | 计分页无此类字段 ⇒ 只能问主办方 |

## 建议的实测顺序（按性价比）

1. **打通通视**（解决位置 bug 或改走浏览器）——这是所有战斗实验的前置。
2. **T4**（表4）——歧义最大、价值最高：对各类装甲车各打若干发，攒 `Report_Attack` 样本。
3. ~~**T7-miss**~~ → **已标定**（修正 = 表5[装甲][随机数2+状态修正] 27/27）；
   下一差分：制造**卧倒/车内**状态，定那四个手册未给数值的状态。
4. **SUP / GAP / ENG**——时序参数，不依赖战果，容易标定。
5. **JM**——间瞄，唯一"手册全无"的域。
6. 其余（PASS/UAV-H/UGV/LM）按需要。
7. **SCORE-\***（计分）——缺得最多：只需**占一个夺控点**、再让**一个单位被整歼**，
   然后各读一次 `Report_All.asp`，就能反推夺控分与歼灭分；
   但若官方肯直接给**7527 计分配置**，就一步到位（见 `docs/计分规则待确认.md`）。
