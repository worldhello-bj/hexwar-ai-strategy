# 能泛化到新观察的策略模型

表格版把整条观察当作一个键。局面只要有一点变化，就可能变成没见过的新键。神经网络版将 JSON 字段编码成共享特征，让相近信息能够使用共同参数。

## 模型如何选择动作

1. 对当前玩家的公开观察和可选动作分别编码。字典键排序，数组保留顺序；数字、字符串、布尔值和空值分开处理。
2. 使用固定哈希桶和通用数字变换，不挑选战术特征。
3. 观察和动作各形成一个小向量，再计算两者的交互项，为每个候选动作打分。
4. 对这些分数做 softmax，抽样选择原始候选动作。只能选择当前接口提供的动作。

默认 2048 个特征桶、32 维向量，使用 NumPy 在 CPU 上运行。两个席位共用模型，当前席位仍是输入的一部分。每场训练只收集学习方自己看到的观察，另一方按均匀随机动作行动。

## 奖励与学习

奖励保持原要求：中间为零，正常终局为本方原始总分。公开比分可以作为观察，绝不改成逐步分差奖励。

算法使用 REINFORCE 和一个观察值基线。基线预测终局总分，用来减少梯度波动，不改变实际奖励。所有决策的回报都是同一个终局分，折扣系数为1。策略目标先对每场的决策求和，再按完成场数平均；值函数按决策平均误差训练。外部步数预算截断的场次不更新参数。

先使用固定随机对手，是为了把“模型有没有学到东西”和“对手也在不断变化”这两个问题分开。这里没有追加手写战术、动作奖励或演示标签。

## 运行

```bash
python -m pip install -r requirements-neural.txt
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m env.neural_train \
  --snapshot samples/demo --episodes 20 --batch-episodes 4 --seed 13 \
  --eval-seeds 2000000 2000001 --max-seconds 1800 --max-steps 1000 \
  --checkpoint /tmp/hexwar-neural-20.json --report /tmp/hexwar-neural-20-report.json
```

Windows 可先设置相应环境变量，再运行同一条 Python 命令。限制 BLAS 线程是为了减少小矩阵计算的线程开销。

续跑传入 `--resume` 和新的输出路径。检查点保存参数、优化器、随机状态、已完成场数、未满批次的经历、场景哈希和预留评测种子；不会把未满批次丢掉。续跑使用检查点中的原始配置。

## 如何判断有没有进步

每轮报告同时固定评测初始模型和训练后模型。两者对阵同一种随机对手，使用相同的独立种子和双方席位。主要看本方终局原始分数，同时记录分差、胜平负、截断和资源占用。

少量场次用于验证代码和测量运行成本。要声称稳定提升，需要多个训练随机种子、更大的预留评测集和独立地图。当前示例场景只有一张固定地图；更换随机种子不等于测试了跨地图泛化。

## 额外的全新种子评测

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m tools.evaluate_neural_checkpoint \
```

工具保持源检查点不变，先检查种子与训练及原预留集合不重叠，再在独立内存副本中评测初始与训练后模型。报告包含各组两个席位平均后的得分变化及描述性标准误。

## 可选的完整公开地图输入

新训练可添加 `--observation-schema 2`。该模式使用 `PublicObservationAdapter`：保留公开双方总分、当前可见信息和最后目击信息，并补齐整张静态棋盘与行列坐标。

模型把动态观察和静态地图放进两个独立特征区，各自归一化；候选动作与公开空间上下文也分别编码。地图格子增加不会挤占动态观察的特征区，也不会缩小动态信息的输入幅度。默认每区2048个桶，所以该模式的观察和动作参数矩阵各有4096行。相同静态地图的哈希特征可复用，地图内容改变时自动重新计算。

例如在前面的运行命令中加入 `--observation-schema 2`，并使用新的检查点和报告文件。模型只根据原始终局分学习，没有额外路线、目标优先级或战术奖励。最终提交给游戏的仍是原始候选动作。

旧检查点继续使用原来的输入。新模式必须开始独立训练，不能把旧检查点直接当作已经学习过地图的模型。续跑自动继承检查点模式；显式要求不同模式会报错。冻结评测也读取保存的模式，报告标明 `observation_schema`。

## 可选的历史终局均值基线

新训练可添加 `--baseline-offset prior_batch_mean`。这是通用数值基线，不修改奖励、原始回报、观察或策略特征。每次更新使用**此前已经处理完的完整批次**的终局分均值作为固定偏移；策略优势为“本场原始终局分 − 历史均值 − 更新前的观察值预测”，值网络拟合相同偏移下的残差。不会使用当前批次均值来计算当前优势。第一批没有历史数据，偏移为零。

批次处理成功后，每个正常完成的场次只计入均值一次，不按决策数量加权。零分与无决策的正常完成场次也计入；截断场次和未满的待处理批次不计入。全无决策批次只更新均值与计数，不执行优化器步。空批次不改变状态。

该选项帮助值网络处理终局分整体偏移，可能降低初期值误差及其对共享梯度裁剪的影响；尚未通过新训练证明策略强度提升。偏移仍会随历史样本更新，早期存在适应过程。

默认 `none` 保持原有计算与检查点格式。启用后检查点保存精确运行均值和样本数，续跑继承模式；显式切换模式会报错，旧检查点不会自动转换。使用相同完整批次边界时，拆分训练调用或中途保存续跑保持精确一致；改变批次大小仍会改变优化过程。
